# Feature map

What Ship implements today, one row per product surface, so an agent can find the
surface it is changing, drive it and prove it. Each row names the surface's files, how it
is entered, what drives it, what success looks like, and the lowest `bin/verify-ship` tier
that proves it. `scripts/check-feature-map.mjs` checks this table against the tree at the
start of `bin/verify-ship quick`, which the Repository contract workflow
(`.github/workflows/repo-contract.yml`) runs on every pull request and push to `main`: a
row naming a path the tree does not have, a file under `src/`, `service/src/`,
`service/spec/`, `service/scripts/`, `tests/`, `scripts/`, `bin/`, `.github/workflows/` or
`.github/scripts/` that no row owns, or a verifier tier the script does not accept fails
the run. A change that adds, moves or removes such a file updates its row in the same
pull request.

Ship is the Registry plugin `dinkus-ship` at the repository root and the hosted Ship
service under `service/` (`README.md`). The charter's later work (live postage, UPS, FedEx,
international labels, automatic purchase, independent order intake; `docs/CHARTER.md`)
has no row until it exists. Paths are backticked; a directory ends with `/` and owns
everything under it.
